1.0 Module Overview & Sub-Module List

Attendance — Daily punch se payroll-ready muster roll tak ka poora process

🎯 Module Purpose

Attendance & Time Management module employee ki daily presence, working hours, shift compliance aur overtime ko multi-mode capture karke automatically process karta hai. Biometric se GPS tak — sabhi capture methods ek single attendance record mein consolidate hote hain, jo directly Payroll (Module 5) aur Leave (Module 4) ke saath sync rehta hai.

📦 8 Sub-Modules

  • 3.1 Attendance Capture Methods
  • 3.2 Shift & Roster Management
  • 3.3 Attendance Processing & Rules Engine
  • 3.4 Regularization & Correction Workflow
  • 3.5 Overtime & Comp-Off Management
  • 3.6 Muster Roll & Statutory Compliance
  • 3.7 Sector-Specific Configuration
  • 3.8 Attendance Dashboard & Analytics

⚠️ Key Business Rules

  • Ek employee ka ek din mein sirf ek final attendance status hoga (System calculated, override sirf approved regularization se)
  • Grace period se zyada late aane par half-day ya LOP (Loss of Pay) auto-trigger hoga as per policy
  • Regularization request sirf 3 working days ke andar raise ho sakti hai, uske baad HR approval mandatory
  • OT sirf pre-approved ya post-facto manager-approved hoga — auto-payment nahi
  • Attendance freeze payroll cut-off date ke baad koi edit allowed nahi (sirf HR override with audit log)
  • Biometric punch missing ho to mobile GPS/web punch backup ke roop mein accept hoga (policy-based)
  • Comp-off earned holiday/weekly-off working par, expiry 90 days (default, configurable)
  • Multi-location employee ka attendance sabhi devices se auto-sync hoga single record mein

✅ Key Metrics System Track Karega

  • Daily Attendance % (Present/Absent/Half-day)
  • Late Coming Trend (Employee & Dept-wise)
  • Average Working Hours vs Standard Hours
  • Overtime Hours & Cost
  • Regularization Request Volume & Approval TAT
  • Comp-off Earned vs Utilized vs Expired
  • Biometric Device Uptime & Mismatch Rate
  • Statutory Compliance Score (Factories Act / AEBAS)

🚫 Rules Engine Validations

  • Grace period cannot exceed 30 mins (statutory reasonableness check)
  • Half-day threshold must be less than full shift hours
  • Late penalty policy cannot result in more than 1 day deduction per month per employee without HR review
  • OT hours capped at statutory limit (e.g. 50 hrs/quarter for Factories Act) — system blocks beyond limit without special approval
  • Minimum rest between two shifts must be ≥ 8 hours before next punch accepted

✅ Auto-Calculation Features

  • Daily batch job (2 AM) processes previous day's punches against shift rules
  • Multi-location punch consolidation into single daily record
  • Leave-Attendance auto-reconciliation (no double deduction)
  • Holiday calendar overlay (company + regional/state holidays)
  • Real-time exception dashboard for HR / managers

⚠️ Regularization Limits

  • Max 3 regularization requests per employee per month (configurable)
  • Requests older than 3 working days require HR-level approval, not just manager
  • Same date cannot be regularized more than once
  • Frequent regularization pattern (>5/month, 3 consecutive months) flagged for HR review

📋 Regularization Types Supported

  • On-Duty / Field Work (no punch expected)
  • Work From Home (ad-hoc, not pre-approved)

7.0 Sub-Module 3.5 — Overtime & Comp-Off Management

Extra hours ka fair compensation — pay ya comp-off, employee choice

⏱️ Overtime Configuration

💰 OT Calculation Example

ScenarioHours Worked ExtraRateCalculation Basis
Weekday, post-shift work2 hrs1.5x(Basic+DA / 208) × 1.5 × hours
Weekly-off working (full day)8 hrs2x(Basic+DA / 208) × 2 × hours, or Comp-off
National Holiday working8 hrs2x + Comp-offDouble pay + 1 comp-off day (statutory)
Night shift extension1.5 hrs1.5x + Night AllowanceOT rate + fixed night allowance

🔄 Comp-Off Lifecycle

  • Earned automatically when employee works on weekly-off/holiday (approved)
  • Credited to comp-off balance within 24 hrs of approval
  • Employee applies comp-off like leave via Leave module (Module 4 sync)
  • Auto-expiry after validity period (default 90 days) with reminder alerts at 15/7/1 day before
  • Expired comp-off can be encashed only if policy allows

⚠️ Statutory OT Limits (Factories Act)

  • Max 50 hours OT per quarter per worker (Factories Act 1948)
  • Total working hours (normal + OT) not to exceed 60 hrs/week
  • Spread-over of work not to exceed 10.5 hours including breaks
  • System hard-blocks OT beyond statutory limit; HR override with justification only

🗄️ Muster Roll Contents

  • Employee ID, Name, Designation, Department
  • Date-wise Present/Absent/Leave/Half-day status
  • Total working days, total present days, OT hours
  • Wages/salary period cross-reference
  • Digital signature of authorized signatory

✅ AEBAS (Govt/PSU) Specific Requirements

  • Aadhaar-based biometric mandatory for all employees
  • Real-time sync with National Informatics Centre (NIC) AEBAS portal
  • Half-day rule: minimum 2 punches (in/out) required, else marked absent
  • Public dashboard visibility of department-wise attendance %

⚠️ Compliance Retention & Audit Rules

  • Muster roll records retained for minimum 3 years (varies by state Shops & Establishment Act)
  • All attendance edits post-freeze logged with editor ID, timestamp, and reason (immutable audit trail)
  • Labour inspector access mode — read-only export for statutory audits
  • OT register cross-validated against payroll OT payout monthly

14.0 Database Design — Attendance Module

Key tables aur relationships

-- Shift Master CREATE TABLE shift_master ( shift_id VARCHAR(20) PK, shift_code VARCHAR(20) UNIQUE, shift_name VARCHAR(50), start_time TIME, end_time TIME, grace_in_mins SMALLINT, grace_out_mins SMALLINT, break_mins SMALLINT, half_day_threshold_hrs DECIMAL(3,1), night_shift BOOLEAN DEFAULT FALSE, is_active BOOLEAN DEFAULT TRUE ); -- Roster / Shift Assignment CREATE TABLE roster ( roster_id BIGINT PK AUTO_INCREMENT, emp_id VARCHAR(20) FK (employees), shift_id VARCHAR(20) FK, roster_date DATE, is_weekly_off BOOLEAN DEFAULT FALSE, is_holiday BOOLEAN DEFAULT FALSE, created_at TIMESTAMP DEFAULT NOW() ); -- Devices CREATE TABLE attendance_devices ( device_id VARCHAR(30) PK, location_id INT FK, device_type ENUM('Biometric-FP','Biometric-Face', 'RFID','GPS','QR','WebPunch','WiFi','BLE'), status ENUM('Online','Offline','Maintenance'), last_sync_at TIMESTAMP );
-- Raw Punch Logs CREATE TABLE punch_logs ( punch_id BIGINT PK AUTO_INCREMENT, emp_id VARCHAR(20) FK (employees), device_id VARCHAR(30) FK, punch_type ENUM('In','Out'), punch_timestamp TIMESTAMP, latitude DECIMAL(9,6), longitude DECIMAL(9,6), is_flagged BOOLEAN DEFAULT FALSE, flag_reason VARCHAR(200) ); -- Daily Attendance (Processed) CREATE TABLE daily_attendance ( attendance_id BIGINT PK AUTO_INCREMENT, emp_id VARCHAR(20) FK, attendance_date DATE, shift_id VARCHAR(20) FK, in_time TIMESTAMP, out_time TIMESTAMP, worked_hours DECIMAL(4,2), status ENUM('Present','Absent','HalfDay', 'Late','OnLeave','MissingPunch','Holiday','WeeklyOff'), ot_hours DECIMAL(4,2) DEFAULT 0, is_frozen BOOLEAN DEFAULT FALSE, UNIQUE(emp_id, attendance_date) ); -- Regularization Requests CREATE TABLE regularization_requests ( request_id VARCHAR(20) PK, emp_id VARCHAR(20) FK, attendance_date DATE, requested_in TIME, requested_out TIME, reason TEXT, proof_path VARCHAR(500), status ENUM('Pending','Approved','Rejected'), approved_by VARCHAR(20) FK (employees), approved_at TIMESTAMP ); -- Comp-off Ledger CREATE TABLE compoff_ledger ( ledger_id BIGINT PK AUTO_INCREMENT, emp_id VARCHAR(20) FK, earned_date DATE, expiry_date DATE, status ENUM('Available','Utilized','Expired','Encashed') );
