## 1.0 Module Overview & Sub-Module List
*Travel & Expense — Trip request se reimbursement tak ka poora T&E lifecycle*

### 🎯 Module Purpose
Travel & Expense (T&E) module employee ki business travel request, booking, expense claim aur reimbursement ko end-to-end manage karta hai. Grade-wise entitlement policy, OCR-based bill capture, aur multi-level approval — sab automated, aur Payroll (Module 5) ke saath directly linked for reimbursement disbursement.

### 📦 8 Sub-Modules
1. **8.1** Travel Request & Booking
2. **8.2** Travel Policy & Entitlement
3. **8.3** Expense Claims & Categories
4. **8.4** Bill/Receipt Management (OCR/GST)
5. **8.5** Approval & Reimbursement Workflow
6. **8.6** Travel Advance Management
7. **8.7** Sector-Specific T&E Configuration
8. **8.8** Travel & Expense Analytics

### ⚠️ Key Business Rules
- Travel booking sirf approved travel request ke against ho sakti hai
- Grade-wise entitlement (flight class, hotel category) hard-enforced, exception ke liye approval mandatory
- Expense claim sirf valid bill/receipt ke saath submit ho sakta hai (except per-km mileage & fixed DA)
- Claims above policy threshold auto-route ho jate hain Finance approval ke liye
- Travel advance ka 100% utilization proof zaroori before next advance request
- Unspent advance auto-recover hota hai next payroll cycle se agar 30 din mein settle nahi hua
- GST-eligible bills automatically tag hote hain input tax credit ke liye Finance ko
- International travel ke liye forex advance aur visa tracking mandatory workflow hai

### ✅ Key Metrics System Track Karega
- Total T&E Spend (Dept/Project-wise)
- Average Reimbursement TAT
- Policy Violation Rate
- Pending Advance Aging
- Budget vs Actual Travel Cost
- Claim Rejection Rate & Reasons
- Most Visited Cities/Countries
- Cost per Trip (avg)

## 4.0 Sub-Module 8.2 — Travel Policy & Entitlement
*Grade-wise flight class, hotel category, per-diem — policy enforced automatically*

### 🎫 Grade-wise Entitlement Matrix

| Grade Band | Flight Class | Train Class | Hotel Category | Daily Allowance (Metro) |
|---|---|---|---|---|
| **Band A (Junior/Executive)** | Economy | AC 3-Tier | 3-Star | ₹1,500/day |
| **Band B (Senior Executive)** | Economy (Premium on >4hr flights) | AC 2-Tier | 4-Star | ₹2,000/day |
| **Band C (Manager)** | Premium Economy | AC 1st Class | 4-Star | ₹2,500/day |
| **Band D (Senior Manager+)** | Business (International only) | AC 1st Class | 5-Star | ₹3,500/day |
| **Band E (Leadership/CXO)** | Business Class | AC 1st Class | 5-Star Luxury | At actuals |

### 📜 Policy Exception Request (if entitlement exceeded) — Fields
- **Entitled Category** (read-only) — e.g. Economy Class, 3-Star Hotel
- **Requested Category** — Premium Economy / 4-Star Hotel
- **Reason for Exception*** — e.g. No economy availability
- **Additional Cost Impact** (read-only) — e.g. ₹4,500 above entitlement
- **Approver** (read-only) — HOD + Finance (mandatory for exceptions)

### ⚠️ Policy Enforcement Rules
- Booking system shows only entitled category options by default
- Any exception requires dual approval (HOD + Finance) regardless of amount
- City-tier classification (Metro/Tier-1/Tier-2) determines DA and hotel budget slabs
- Policy version history maintained — applies policy active on travel date

### 🏙️ City Tier Classification (Sample)
- **Metro:** Mumbai, Delhi, Bangalore, Chennai, Kolkata, Hyderabad, Pune
- **Tier-1:** Ahmedabad, Jaipur, Lucknow, Chandigarh
- **Tier-2:** All other cities
- **International:** Country-wise per-diem table (US, UK, Singapore, etc.)

## 5.0 Sub-Module 8.3 — Expense Claims & Categories
*Category-wise claim submission — mileage se entertainment tak*

### 💳 Expense Category Master

| Category | Claim Basis | Bill Required? | Special Rule |
|---|---|---|---|
| **Airfare / Train Fare** | Actual (against booking) | Yes - E-ticket | Pre-approved via travel request |
| **Hotel Accommodation** | Actual, within grade entitlement | Yes - Hotel invoice | Category cap enforced |
| **Local Conveyance / Cab** | Actual with bill | Yes | Route/purpose mandatory for high amounts |
| **Mileage (Own Vehicle)** | Per KM rate × distance | No - system calculated | ₹8-12/km (vehicle type based) |
| **Daily Allowance (DA)** | Fixed per day, city-tier based | No - auto-calculated | Auto-credited for full travel days |
| **Meal Allowance** | Fixed or actual (policy-based) | Policy-dependent | City-wise slab |
| **Entertainment / Client Meeting** | Actual with bill | Yes + guest details | Guest name, company, purpose mandatory |
| **Communication (Mobile/Internet)** | Actual or fixed monthly cap | Yes (if actual) | Business-use only |
| **Visa & Travel Insurance** | Actual | Yes | International travel only |
| **Miscellaneous** | Actual with justification | Yes | Requires detailed description, capped amount |

### 💳 Expense Claim Form (Line Item) — Fields
- **Expense Category*** — Hotel Accommodation / Local Conveyance / Meal Allowance
- **Date of Expense*** — date
- **Amount*** — number, e.g. 4500
- **Currency** — INR / USD / EUR
- **Linked Travel Request** (read-only) — e.g. TR-2024-0234
- **Project / Cost Center** (read-only) — e.g. Project Alpha - Client XYZ
- **Within Policy Limit?** (read-only) — e.g. ✅ Yes (Limit: ₹5,000)
- **Bill/Receipt Upload*** — Upload via Mobile Camera (OCR auto-fill enabled)

### ⚠️ Claim Submission Validations
- Expense date must fall within approved travel request date range
- Duplicate bill detection (same amount + date + category flagged for review)
- Claims must be submitted within TAT (e.g. 7 days post-trip completion, policy configurable)
- Amount exceeding category limit auto-flagged, requires justification note
- Personal expenses (non-business) blocked from submission via category restriction

## 6.0 Sub-Module 8.4 — Bill/Receipt Management (OCR/GST)
*Mobile camera capture, auto-read amount, GST tagging for input tax credit*

### 📷 OCR Receipt Capture Features
- Mobile camera scan with auto-crop and enhancement
- Auto-extraction: Amount, Date, Vendor Name, GST Number
- Employee reviews & confirms extracted data before submission
- Blurry/unreadable receipt flagged for manual re-upload
- Supports multi-page bills (PDF/multiple images)

### ✅ GST Capture & Input Tax Credit
- Vendor GSTIN auto-validated against GST portal format
- GST amount separately captured (CGST/SGST/IGST breakup)
- GST-eligible bills tagged for Finance's Input Tax Credit (ITC) claim
- Non-GST registered vendor bills flagged, no ITC eligibility

### 🧾 OCR Extraction Field Mapping

| Extracted Field | Source | Confidence Handling |
|---|---|---|
| Total Amount | Bill footer/total line | High confidence auto-fill; low confidence flags for manual entry |
| Bill Date | Header/date stamp | Cross-validated against travel date range |
| Vendor Name | Bill header | Matched against known vendor database where possible |
| GSTIN | Bill header/footer | Format validation (15-character alphanumeric) |
| GST Amount | Tax breakup section | Auto-split CGST/SGST/IGST if present |

### 🚫 Credit Card Reconciliation
- Corporate credit card statement auto-imported and matched against submitted claims
- Unmatched credit card transactions flagged for employee to submit corresponding claim
- Personal expenses on corporate card flagged for recovery via payroll deduction
- Reconciliation report generated monthly for Finance review

## 7.0 Sub-Module 8.5 — Approval & Reimbursement Workflow
*Manager to Finance approval, exception handling, payout via payroll/bank*

### Workflow Steps

| # | Step | Role | Description |
|---|---|---|---|
| 1 | Claim Submitted | 👤 Employee | All line items compiled |
| 2 | Manager Review | 👤 Reporting Manager | Policy & business relevance check |
| 3 | Amount > Threshold? | 🤖 System Auto | Route to Finance if high-value |
| 4 | Finance Approval | 👤 Finance Team | For high-value/exception claims |
| 5 | ✅ Claim Approved | 🤖 System Auto | Net payable calculated |
| 5b | ❌ Rejected | 🤖 System Auto | Reason logged, resubmission allowed |
| 6 | Reimbursement Run | 🤖 System Auto | Weekly/monthly batch |
| 7 | ✅ Amount Disbursed | 🤖 System Auto | Payroll add-on or direct bank |

### ⚠️ Exception Handling
- Policy violation claims require written justification from employee
- Manager can approve minor exceptions (<10% over limit); larger exceptions escalate to Finance
- Rejected claims can be resubmitted once with corrections, then require HR mediation
- Repeated policy violations (3+ in a quarter) flagged for HR/manager counselling

### ✅ Reimbursement Methods
- Payroll add-on — included in next salary cycle (most common)
- Direct bank transfer — for urgent/high-value claims, separate from payroll
- TAT tracking: target 5-7 working days from approval to disbursement
- Reimbursement status visible real-time to employee (Submitted → Approved → Paid)

## 8.0 Sub-Module 8.6 — Travel Advance Management
*Estimated advance disbursement, utilization tracking, auto-recovery*

### 💵 Travel Advance Request — Fields
- **Linked Travel Request*** (read-only) — e.g. TR-2024-0234
- **Estimated Trip Cost** — number, e.g. 25000
- **Advance Requested (max 80%)** — number, e.g. 20000
- **Outstanding Previous Advances** (read-only) — e.g. ₹0 - Clear
- **Disbursement Mode** — Bank Transfer / Cash
- **Expected Settlement Date** — date

### 🔄 Advance Lifecycle

| Stage | Rule | System Action |
|---|---|---|
| Advance Request | Max 80% of estimated trip cost | Blocked if prior advance unsettled |
| Advance Disbursed | Approved by manager, processed by Finance | Ledger entry created, outstanding balance tracked |
| Trip Completion | Employee submits expense claims | Claims auto-adjusted against advance |
| Settlement Window | 30 days from trip end (policy configurable) | Reminder notifications at 15/7/1 days |
| Unspent Advance Recovery | If claims < advance amount | Auto-deducted from next payroll cycle |
| Overdue Settlement | Beyond settlement window, no claim submitted | Escalated to HR/Finance, full recovery triggered |

### ⚠️ Advance Control Rules
- New advance blocked until previous advance is fully settled (claims submitted or recovered)
- Advance cannot exceed grade-wise cap regardless of estimated trip cost
- Cash advances require physical acknowledgment/signature

### 📊 Advance Aging Tracking
- **0-15 days:** Normal (green)
- **16-30 days:** Reminder sent (yellow)
- **31+ days:** Overdue, recovery initiated (red)

## 9.0 Sub-Module 8.7 — Sector-Specific T&E Configuration
*Har industry ki alag travel zaroorat — configurable policy templates*

### 🏭 Sector-Wise T&E Matrix

| Sector | Special Requirement | Configuration | Priority |
|---|---|---|---|
| IT / Software | Client-site travel, onsite deputation expense | Long-term deputation allowance separate from short-trip DA | High |
| Sales / FMCG | High-frequency local travel, field sales expense | Simplified mobile-first claim for frequent travelers | Critical |
| Manufacturing | Site visits, vendor/supplier travel | Project-linked cost allocation mandatory | Medium |
| Healthcare | Conference/CME travel for doctors, sponsored trips | Sponsor disclosure tracking (compliance) | High |
| Consulting | Very high travel frequency, client billable expenses | Billable vs non-billable expense tagging for client invoicing | Critical |
| Construction | Site visits, remote location travel with limited infra | Offline claim capture with delayed sync | Medium |
| Government / PSU | TA/DA rules per government scale, LTC integration | Government TA/DA rate table, audit-ready documentation | Critical |
| Education | Faculty conference/seminar travel | Academic grant-linked expense tracking | Low |

### 💼 Consulting — Billable Expense Tagging
- Every expense line tagged Billable / Non-Billable to client
- Client-approved expense categories configured per engagement
- Auto-export to client invoicing system for billable expenses
- Markup % applied where contractually agreed

### 🏛️ Government / PSU — TA/DA Rules
- TA/DA as per Pay Level (7th CPC linked entitlement)
- Halting allowance for overnight stays (grade-based)
- LTC (Leave Travel Concession) travel claims integrated with Leave Module
- Audit trail mandatory for CAG (Comptroller & Auditor General) review readiness

## 14.0 Database Design — Travel & Expense Module
*Key tables aur relationships*

```sql
-- Travel Request
CREATE TABLE travel_requests (
  request_id        VARCHAR(20) PK,
  emp_id            VARCHAR(20) FK (employees),
  travel_type       ENUM('Domestic','International'),
  from_city         VARCHAR(50),
  to_city           VARCHAR(50),
  start_date        DATE,
  end_date          DATE,
  purpose           VARCHAR(200),
  project_code      VARCHAR(30),
  status            ENUM('Pending','Approved',
                       'Rejected','Completed')
);

-- Entitlement Master
CREATE TABLE travel_entitlement (
  entitlement_id    BIGINT PK AUTO_INCREMENT,
  grade_band        VARCHAR(20),
  flight_class      VARCHAR(30),
  hotel_category    VARCHAR(20),
  da_metro          DECIMAL(8,2),
  da_nonmetro       DECIMAL(8,2)
);

-- Travel Advance
CREATE TABLE travel_advance (
  advance_id        VARCHAR(20) PK,
  emp_id            VARCHAR(20) FK,
  request_id        VARCHAR(20) FK,
  amount            DECIMAL(10,2),
  disbursed_at      TIMESTAMP,
  status            ENUM('Outstanding','Settled',
                       'PartiallySettled','Recovered')
);

-- Expense Claims
CREATE TABLE expense_claims (
  claim_id          VARCHAR(20) PK,
  emp_id            VARCHAR(20) FK,
  request_id        VARCHAR(20) FK,
  total_amount      DECIMAL(10,2),
  advance_adjusted  DECIMAL(10,2),
  net_payable       DECIMAL(10,2),
  status            ENUM('Draft','Submitted',
                       'ManagerApproved','FinanceApproved',
                       'Rejected','Reimbursed'),
  submitted_at      TIMESTAMP
);

-- Expense Line Items
CREATE TABLE expense_line_items (
  line_item_id      BIGINT PK AUTO_INCREMENT,
  claim_id          VARCHAR(20) FK,
  category          VARCHAR(50),
  expense_date      DATE,
  amount            DECIMAL(10,2),
  gst_amount        DECIMAL(8,2),
  vendor_gstin      VARCHAR(15),
  bill_path         VARCHAR(500),
  is_policy_compliant BOOLEAN
);

-- OCR Extraction Log
CREATE TABLE ocr_extraction_log (
  extraction_id     BIGINT PK AUTO_INCREMENT,
  line_item_id      BIGINT FK,
  extracted_amount  DECIMAL(10,2),
  extracted_date    DATE,
  extracted_vendor  VARCHAR(100),
  confidence_score  DECIMAL(4,2)
);

-- Reimbursement Batch
```
