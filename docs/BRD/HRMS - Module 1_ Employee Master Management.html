1.0 Module Overview & Business Purpose

Employee Master — the foundation of your HRMS. Every other module starts here.

🎯 Module Purpose

Employee Master Management is the foundation module of the HRMS. It stores every employee's complete information — from personal and professional details to financial and legal data. All other modules — Payroll, Attendance, Leave, Performance — depend on this data.

🏢 Who Uses This Module?

  • HR Admin — enters and manages employee data
  • Employee — views and self-updates their own profile
  • Manager — views team member data
  • Payroll Team — uses data for salary processing
  • Compliance Officer — verifies legal and statutory data
  • Auditor — read-only access

⚠️ Critical Business Rules

  • Employee ID must be globally unique
  • Aadhaar number cannot be duplicated
  • PAN card cannot be duplicated
  • Bank account must be verified before payroll processing
  • Photo is mandatory for ID card generation
  • Emergency contact is mandatory
  • Probation period is a mandatory field
  • Salary structure can only be assigned after the date of joining

12.0 Database Design — Key Tables

Employee Master — main tables and relationships

-- Main Employee Table CREATE TABLE employees ( emp_id VARCHAR(20) PRIMARY KEY, company_id INT NOT NULL FK, title VARCHAR(10), first_name VARCHAR(50) NOT NULL, middle_name VARCHAR(50), last_name VARCHAR(50) NOT NULL, full_name_aadhaar VARCHAR(100), date_of_birth DATE NOT NULL, gender ENUM('Male','Female','Trans','NDS'), blood_group ENUM('A+','A-','B+','B-',...), marital_status ENUM('Single','Married',...), nationality VARCHAR(30), category ENUM('General','OBC','SC','ST','EWS'), pwd_status ENUM('No','Visual','Hearing',...), father_name VARCHAR(100), spouse_name VARCHAR(100), photo_path VARCHAR(500), emp_status ENUM('Active','Inactive','Exited'), date_of_joining DATE NOT NULL, probation_months TINYINT DEFAULT 6, created_by INT FK (users), created_at TIMESTAMP DEFAULT NOW(), updated_at TIMESTAMP ON UPDATE NOW() );
-- Employment Details Table CREATE TABLE emp_employment ( id INT PRIMARY KEY AUTO_INCREMENT, emp_id VARCHAR(20) FK, dept_id INT FK (departments), designation_id INT FK (designations), grade_id INT FK (grades), location_id INT FK (locations), cost_center_id INT FK (cost_centers), l1_manager_id VARCHAR(20) FK (employees), l2_manager_id VARCHAR(20) FK (employees), emp_type ENUM('Permanent','Contract',...), shift_id INT FK (shifts), payroll_group INT FK (payroll_groups), notice_period SMALLINT DEFAULT 90, effective_from DATE NOT NULL, effective_to DATE -- History maintained (SCD Type 2) ); -- Banking Table (Encrypted) CREATE TABLE emp_banking ( id INT PRIMARY KEY, emp_id VARCHAR(20) FK, bank_name VARCHAR(100), account_no VARBINARY(500), -- AES Encrypted ifsc_code VARCHAR(11), pan_number VARBINARY(500), -- AES Encrypted aadhaar_last4 CHAR(4), uan_number VARCHAR(12), is_primary BOOLEAN DEFAULT TRUE, verified_at TIMESTAMP, verified_method ENUM('PennyDrop','Manual') );

⚠️ Important: History Tracking (SCD Type 2)

The Employment Details table uses SCD Type 2 (Slowly Changing Dimension) — on every change, a new row is inserted and the previous row's effective_to date is set. This maintains a full history of which department and grade an employee was in at any point in time. Critical for payroll historical accuracy.

📌 Bulk Upload Business Rules

  • Maximum 5,000 rows per upload batch
  • File size limit: 10 MB
  • Only HR Admin and Super Admin roles can perform bulk import
  • Duplicate PAN / Aadhaar cause the row to be skipped (with error)
  • Employee IDs are auto-generated if left blank
  • Penny drop bank verification runs asynchronously after import
  • All bulk imports are logged in the audit trail with uploader's ID
  • An import summary email is sent to the HR Admin upon completion
  • Use dry_run=true in the API to validate without saving
  • Template version must match the current system version (v3.2+)

⚠️ Fields NOT Supported in Bulk Upload

  • Employee photo — must be uploaded individually or via Document Upload
  • KYC documents (Aadhaar scan, PAN scan) — use Document Upload module
  • Educational certificates — use Document Upload module
  • Multiple bank accounts — only primary account via bulk upload
  • Family / dependent details — must be entered individually

✅ Document Upload Business Rules

  • All uploaded files are stored in AES-256 encrypted cloud storage
  • Direct file URLs are never exposed — only short-lived signed URLs (15 min TTL)
  • Employees can upload their own documents; HR Admin can upload for anyone
  • Managers can view (not upload/delete) documents for their direct reports
  • Every upload is recorded in the audit trail (who uploaded, when, from which IP)
  • System sends an email alert 30, 60, and 90 days before document expiry
  • Aadhaar and PAN document numbers are cross-validated via e-KYC API on upload
  • HR Admin can mark documents as Verified or Rejected with mandatory remarks
  • Payroll processing is blocked until all mandatory KYC documents are verified
  • Maximum 100 documents per employee allowed (soft limit; configurable)
