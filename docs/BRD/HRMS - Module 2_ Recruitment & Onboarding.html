1.0 Module Overview & Sub-Module List

Recruitment — Complete process from job posting to final joining

🎯 Module Purpose

The Recruitment & Onboarding module manages the complete hiring lifecycle — from manpower request to the employee's first day. Job posting, candidate tracking, interview scheduling, offer letters, document collection, and induction — everything in one system.

📦 10 Sub-Modules

  • 2.1 Manpower Requisition (MRF)
  • 2.2 Job Posting Management
  • 2.3 Candidate Database / CV Bank
  • 2.4 Application Tracking System (ATS)
  • 2.5 Screening & Shortlisting
  • 2.6 Interview Management
  • 2.7 Selection & Offer Management
  • 2.8 Background Verification (BGV)
  • 2.9 Pre-Joining Engagement
  • 2.10 Onboarding & Induction

⚠️ Key Business Rules

  • Hiring cannot happen outside MRF-approved headcount
  • Offer letter will only be issued after BGV is initiated
  • Salary offer cannot exceed the grade-approved band without HOD+HR+COO approval
  • The same candidate cannot be considered for 2 positions simultaneously (within the same company)
  • A rejected candidate cannot apply for the same role for 6 months
  • Interview panel must have at least 1 technical and 1 HR interviewer
  • Offer validity: max 30 days from offer date
  • Candidate portal access expires upon offer acceptance; onboarding portal is activated

✅ Key Metrics the System Will Track

  • Time to Hire (MRF to Joining)
  • Time to Fill (MRF to Offer Accept)
  • Cost per Hire
  • Offer Acceptance Rate
  • Source-wise Conversion Rate
  • Interview-to-Offer Ratio
  • Onboarding Completion Score
  • Early Attrition (< 90 days)

🤖 AI Scoring Algorithm

  • Skills Match (35%): Required skills vs candidate skills — NLP keyword matching + semantic similarity
  • Experience (25%): Years of experience within MRF min-max range
  • Qualification (20%): Degree match against requirement
  • Salary Fit (10%): Expected CTC within MRF budget range
  • Location (10%): City match or relocation willingness

✅ Auto-Action Based on Score

  • Score ≥ 80%: Auto-shortlist + Recruiter notified
  • Score 60-79%: Manual review required
  • Score 40-59%: Maybe pile — recruiter reviews
  • Score < 40%: Auto-reject + polite email sent
  • Deal breaker Q failed: Instant reject regardless of score

⚠️ Duplicate Candidate Check

  • Same mobile = Duplicate alert
  • Same email = Duplicate alert
  • Same name + same employer + same exp = Possible duplicate flag
  • Same candidate applied to same role in < 6 months = Blocked

⚙️ Round Configuration — Business Rules

✅ What Can Be Configured Per Round

  • Add Round: Create a new custom round (name, type, sequence)
  • Remove Round: Disable any round for this job — candidate skips it automatically
  • Merge Rounds: Two rounds conducted simultaneously in one session (e.g. Technical + Managerial as a single Panel)
  • Reorder: Drag-and-drop to change round sequence
  • Selection Rule: Set Unanimous / Majority / Any One per round independently
  • Format: Panel or Sequential per round
  • Mandatory/Optional: Optional rounds can be skipped by recruiter per candidate

🔴 Configuration Constraints

  • Minimum 2 rounds mandatory — Phone Screening + at least 1 interview round
  • Round 1 (Screening) cannot be removed
  • Merged rounds share the same date/time/venue — counted as 1 step in pipeline
  • A round can only be merged with an adjacent round (next or previous)
  • Max 8 rounds per pipeline (including merged)
  • Configuration locked once first candidate reaches Round 2 — changes need HR Head approval
  • CXO Round removal requires COO approval if position is Grade C or above

📅 Interview Schedule Form

👥 Panel Interview Support — Multiple Interviewers in One Session

A round can be conducted as a Panel Interview where all assigned interviewers sit together with the candidate at the same time, or as Sequential 1:1 rounds scheduled separately. In both cases, every interviewer must submit their own individual Assessment Sheet.

  • ✅ Panel Interview = same date, time, and room for all interviewers
  • ✅ Sequential = different time slots per interviewer (same or different days)
  • 🔴 Unanimous Rule: If even ONE interviewer marks "Not Recommended" or "Reject" — candidate is automatically marked Not Selected for that round. No override without HR Head approval.

🔴 Unanimous Selection Rule — System Logic

  • Default Rule: ALL interviewers must submit "Recommend" or "Strongly Recommend" for the candidate to move to the next round
  • Even 1 "Not Recommended": Candidate is automatically marked Not Selected for that round — no exceptions without override
  • Even 1 "Hold": Round marked as On Hold — HR Head review required before proceeding
  • Pending Assessment: If any interviewer hasn't submitted within 24 hours, HR is escalated — round result stays Pending
  • Override Process: HR Head can override with written justification logged in the system — visible in audit trail
  • Panel vs Sequential: Rule applies equally whether it was a panel interview or separate 1:1 rounds — all assessments are consolidated
  • Candidate Notification: Auto-email sent within 2 hours of Not Selected status — polite rejection template used

⚠️ BGV Discrepancy Handling

  • Minor Discrepancy: HR reviews, candidate given chance to explain. HR decides join/reject
  • Major Discrepancy (fake docs, false employment): Instant offer revocation + blacklist candidate
  • Criminal Record: Case-by-case HR+Legal review. Nature of crime matters
  • BGV Pending on DOJ: Conditional joining allowed for low-risk roles. Restricted access till BGV clear
  • Blacklisted candidates cannot apply to same company for 5 years

📋 BGV API Integrations

  • Aadhaar: UIDAI API — name, DOB, address verify
  • PAN: NSDL API — name, status verify
  • Driving License: Sarathi portal API
  • Education: DigiLocker pull (for Govt issued degrees)
  • CIBIL: TransUnion CIBIL API (consent required)
  • MCA21: Company registration verify for previous employer
  • EPFO: UAN verify, previous employer PF records

14.0 Database Design — Recruitment Module

Key tables and relationships

-- Manpower Requisition CREATE TABLE mrf ( mrf_id VARCHAR(20) PK, company_id INT FK, dept_id INT FK, requested_by VARCHAR(20) FK (employees), position_title VARCHAR(100) NOT NULL, designation_id INT FK, grade_id INT FK, no_of_positions TINYINT NOT NULL, position_type ENUM('New','Backfill','Contract','Temp'), exp_min_years DECIMAL(4,1), exp_max_years DECIMAL(4,1), ctc_min_lpa DECIMAL(5,2), ctc_max_lpa DECIMAL(5,2), expected_doj DATE, priority ENUM('Critical','High','Medium','Normal'), key_skills JSON, jd_text TEXT, status ENUM('Draft','Pending','Approved','Closed'), approved_by VARCHAR(20) FK (employees), approved_at TIMESTAMP, created_at TIMESTAMP DEFAULT NOW() ); -- Job Postings CREATE TABLE job_postings ( job_id VARCHAR(20) PK, mrf_id VARCHAR(20) FK, job_title VARCHAR(100), jd_full LONGTEXT, channels JSON, -- ["naukri","linkedin","internal"] posted_at TIMESTAMP, expiry_date DATE, show_salary BOOLEAN DEFAULT FALSE, status ENUM('Draft','Active','Closed','Expired') );
-- Candidate Master CREATE TABLE candidates ( candidate_id VARCHAR(20) PK, first_name VARCHAR(50), last_name VARCHAR(50), email VARCHAR(100) UNIQUE, mobile VARCHAR(15) UNIQUE, total_exp_years DECIMAL(4,1), current_ctc_lpa DECIMAL(5,2), expected_ctc_lpa DECIMAL(5,2), notice_period_days SMALLINT, resume_path VARCHAR(500), source ENUM('Naukri','LinkedIn','Referral','Walk-in'...), referred_by VARCHAR(20) FK (employees), blacklisted BOOLEAN DEFAULT FALSE, blacklist_reason TEXT ); -- Applications (Candidate applies to Job) CREATE TABLE applications ( application_id VARCHAR(20) PK, candidate_id VARCHAR(20) FK, job_id VARCHAR(20) FK, mrf_id VARCHAR(20) FK, ai_match_score DECIMAL(5,2), current_stage ENUM('Applied','Screened','Phone', 'Technical','HR','Final','Offer','Joined','Rejected'), rejection_reason VARCHAR(200), applied_at TIMESTAMP ); -- Interview Schedule CREATE TABLE interviews ( interview_id INT PK AUTO_INCREMENT, application_id VARCHAR(20) FK, round_number TINYINT, interview_date DATE, interview_time TIME, mode ENUM('InPerson','Video','Phone'), meeting_link VARCHAR(500), interviewers JSON, -- [emp_ids] status ENUM('Scheduled','Completed','Cancelled','NoShow') ); -- Offers CREATE TABLE offers ( offer_id VARCHAR(20) PK, application_id VARCHAR(20) FK, ctc_breakup JSON, -- Full salary structure offer_date DATE, offer_validity DATE, expected_doj DATE, esign_status ENUM('Pending','Signed','Declined'), esign_timestamp TIMESTAMP, status ENUM('Draft','Sent','Accepted','Rejected','Revoked','Expired') );
